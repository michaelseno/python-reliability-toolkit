Privacy and safety guarantees

The audit is designed to minimize production risk and sensitive data exposure.

  • Production API testing requires written client waiver/agreement and internal approval before execution.
  • Bearer tokens are treated as confidential credentials and excluded from reports and CSV exports.
  • Reports and CSV exports contain sanitized metadata only.
  • Raw logs, raw responses, raw response bodies, raw headers, trace logs, and stack traces are not displayed or persisted by default.
  • Any raw diagnostic artifact collection, display, inclusion, or persistence exception requires explicit client request plus written approval/reference.
  • Sanitized metadata is retained for 90 days, then exported to CSV and emailed through the approved retention workflow.

FAQ

  • How many endpoints are included?

    The standard audit covers up to 10 unique METHOD + PATH combinations. The same path with different methods counts as separate endpoints.

  • Can production APIs be tested?

    Yes, only after written client waiver/agreement and internal production approval are complete. Missing either approval blocks production testing.

  • What authentication is supported?

    Bearer-token authentication is supported first. Token values are handled as sensitive credentials and are excluded from reports and CSV exports.

  • What data is retained?

    Sanitized metadata is retained for 90 days. Raw logs, raw responses, raw response bodies, raw headers, trace logs, and stack traces are not displayed or stored by default.

  • What if latency thresholds are not provided?

    The report shows observed latency only. It does not label latency as pass or fail unless client-provided thresholds exist.

  • Is resilience or burst testing included?

    No. Resilience/burst testing is optional, outside the standard workflow, and requires separate written approval before execution.
